1. 仮想ウェブカメラとは

仮想ウェブカメラ (Virtual Webcam) とは、物理的なカメラデバイスがなくても、ソフトウェアが生成した映像をあたかもウェブカメラの映像であるかのように OS に認識させる仕組みです。

IronHSP の hspvcam プラグインを使うと、HSP プログラムの画面描画内容をリアルタイムに仮想カメラとして配信できます。これにより、HSP で作成したアニメーション、ゲーム画面、テキストオーバーレイなどを Zoom, Google Meet, OBS Studio, Discord 等のアプリケーションで「カメラ映像」として使用できます。

従来の hspycp との違い

旧 HSP プラグイン hspycp は DirectShow の ycapture ライブラリを使って仮想キャプチャデバイスを直接登録する方式でした。この方式は以下の問題がありました:

  • DirectShow フィルタの登録に regsvr32 (管理者権限) が必要
  • Windows 10 以降で DirectShow の互換性問題が発生しやすい
  • 64bit 対応が困難

hspvcam は名前付き共有メモリ方式を採用し、HSP プロセスとブリッジプロセスを分離することで、これらの問題を回避しています。

2. 主なユースケース

  • 配信・実況 — HSP で作成したゲーム画面やアニメーションを OBS Studio 経由でライブ配信
  • ビデオ会議 — Zoom / Google Meet / Teams で HSP 製のオーバーレイ (時計、字幕、背景エフェクト) をカメラ映像として送信
  • 録画 — HSP の描画内容を仮想カメラ経由で動画として録画
  • プレゼンテーション — リアルタイムでデータ可視化やインタラクティブなデモを「カメラ」として表示
  • 映像エフェクト — 物理カメラの映像を HSP で加工し、仮想カメラとして再出力 (hspcv4 と組み合わせ)
  • テスト・開発 — カメラ入力を必要とするアプリケーションのテスト用にダミー映像を供給

3. アーキテクチャ

hspvcam は「プロデューサ - コンシューマ」モデルで動作します。HSP プログラム (プロデューサ) がフレームデータを共有メモリに書き込み、外部のブリッジプロセス (コンシューマ) がそれを読み出して OS のカメラデバイスとして公開します。

HSP プログラム (プロデューサ) | | hspvcam.dll API (vcam_create / vcam_send / ...) | v 名前付き共有メモリ [IronHSP_VCam_{handle}] | VCamSharedHeader + BGRA ピクセルデータ | | 名前付きイベント [IronHSP_VCam_Event_{handle}] | フレーム更新の通知 v ブリッジプロセス (コンシューマ) | | DirectShow Source Filter / Media Foundation Virtual Camera | v OS カメラデバイス一覧 | v Zoom / OBS / Teams / Discord / ...

この設計のメリット

  • プロセス分離 — HSP プロセスがクラッシュしてもブリッジプロセスは影響を受けない (逆も同様)
  • 権限分離 — regsvr32 が必要なのはブリッジプロセスのインストール時のみ。HSP 実行時は一般ユーザ権限で動作
  • 柔軟性 — ブリッジプロセスを差し替えることで DirectShow / Media Foundation / OBS Virtual Camera 等の異なるバックエンドに対応可能
  • 32/64bit 混在 — 共有メモリはプロセス間共有なので、32bit HSP から 64bit ブリッジ (またはその逆) にフレームを渡せる

4.2 ブリッジプロセスの選択

仮想カメラとして OS に認識させるには、ブリッジプロセスが必要です。以下のいずれかの方法で利用できます:

方法 A: OBS Virtual Camera (推奨)

OBS Studio をインストールすると「OBS Virtual Camera」が OS に登録されます。OBS のシーンソースとして「ウィンドウキャプチャ」で HSP ウィンドウを選択すれば、ブリッジプロセスなしでも仮想カメラとして使えます。

ただし、この方法では hspvcam.dll は不要で、HSP 側から配信制御はできません。

方法 B: IronHSP VCam Bridge (専用ブリッジ)

IronHSP 専用のブリッジプロセスを使用します。共有メモリからフレームを読み出して DirectShow ソースフィルタに供給するため、HSP プログラムから完全に配信を制御できます。

  1. ブリッジ DLL (IronHSP_VCamBridge.dll) を管理者権限で登録: 
    regsvr32 IronHSP_VCamBridge.dll
  2. ブリッジプロセス (vcam_bridge.exe) を起動: 
    vcam_bridge.exe --handle 1
  3. HSP プログラムから vcam_create で同じハンドル番号を使用
注意: ブリッジプロセス (vcam_bridge.exe / IronHSP_VCamBridge.dll) は現在開発中です。当面は OBS Virtual Camera との併用、または共有メモリを読み出す独自アプリケーションの作成をお勧めします。

5. クイックスタート

最小限のコードで仮想カメラにフレームを送信する例です:

#include "iron_vcam.hsp"

    ; 640x480, 30fps で仮想カメラを作成
    vcam_create 640, 480, 30
    cam = stat
    if cam == 0 : dialog "失敗" : end

    screen 0, 640, 480
    title "Virtual Webcam"

    repeat
        redraw 0
        color 0, 0, 0 : boxf
        color 255, 255, 255
        pos 10, 10 : mes "Hello Virtual Camera!"
        pos 10, 30 : mes "Frame: " + cnt
        redraw 1

        ; カレントスクリーンを送信
        vcam_send cam

        await 33   ; 約 30fps
    loop

7. 共有メモリ仕様

ブリッジプロセスを独自に実装する場合の共有メモリレイアウトです。

7.1 命名規則

オブジェクト名前パターン説明
共有メモリIronHSP_VCam_{handle}ヘッダー + ピクセルデータ
イベントIronHSP_VCam_Event_{handle}フレーム送信通知 (自動リセット)

7.2 ヘッダー構造体

struct VCamSharedHeader {
    int width;           // フレーム幅 (ピクセル)
    int height;          // フレーム高さ (ピクセル)
    int fps;             // フレームレート
    int frame_counter;   // フレーム番号 (送信ごとにインクリメント)
    int consumer_alive;  // コンシューマが書き込む接続フラグ (0/1)
    int reserved[3];     // 将来の拡張用 (32 bytes 境界)
};
// ヘッダーの直後に BGRA ピクセルデータが続く
// サイズ: width * height * 4 バイト

7.3 ピクセルフォーマット

  • フォーマット: BGRA (Blue, Green, Red, Alpha)
  • ビット深度: 各チャンネル 8 bit (32 bpp)
  • 走査方向: トップダウン (先頭バイトが左上ピクセル)
  • ストライド: width * 4 (パディングなし)
  • Alpha: 通常は 255 (不透明)。ブリッジ側で合成に使用可能

7.4 同期プロトコル

  1. プロデューサ (HSP) が共有メモリにピクセルデータを書き込む
  2. プロデューサが frame_counter をインクリメント
  3. プロデューサがイベントをシグナル状態にする (SetEvent)
  4. コンシューマ (ブリッジ) が WaitForSingleObject でイベントを待機
  5. コンシューマが共有メモリからピクセルデータを読み出す
  6. コンシューマは consumer_alive を 1 に設定して接続を通知
排他制御について: 現在の実装ではプロデューサとコンシューマ間でミューテックスによる排他は行っていません。frame_counter の変化を確認することで新フレームの到着を検知できます。1 フレームの書き込みが途中で読まれるティアリング (tearing) が問題になる場合は、ダブルバッファリングの導入を検討してください。

8. ブリッジプロセスについて

IronHSP 専用のブリッジプロセスは現在開発中です。当面は以下の方法で仮想カメラ機能を利用できます:

8.1 OBS Virtual Camera との併用

最も簡単な方法です。hspvcam を使わず、OBS Studio のウィンドウキャプチャ機能で HSP ウィンドウを取り込み、OBS の「仮想カメラ開始」ボタンで配信します。

8.2 独自ブリッジの実装

共有メモリ仕様 (第 7 章) に基づいて独自のブリッジプロセスを実装できます。C# / Python / C++ 等で共有メモリを開き、フレームを読み出して仮想カメラデバイスに供給します。

Python での読み出し例:

import mmap
import struct
import time

# 共有メモリを開く (handle=1 の場合)
shm = mmap.mmap(-1, 32 + 640*480*4, tagname="IronHSP_VCam_1", access=mmap.ACCESS_READ)

# ヘッダーの読み取り
header = struct.unpack("8i", shm[:32])
width, height, fps = header[0], header[1], header[2]
frame_counter = header[3]

print(f"Resolution: {width}x{height} @ {fps}fps")
print(f"Frame: {frame_counter}")

# ピクセルデータの読み取り (BGRA)
pixel_data = shm[32:32 + width*height*4]

shm.close()

8.3 DirectShow ソースフィルタの実装

本格的な仮想カメラデバイスとして OS に認識させるには、DirectShow ソースフィルタ (IBaseFilter + IPin + IMediaSample) を実装した COM DLL を作成し、regsvr32 で登録する必要があります。これは旧 hspycp の ycapture ライブラリと同等の実装です。

8.4 Media Foundation Virtual Camera (Windows 11+)

Windows 11 22H2 以降では、Media Foundation の IMFVirtualCamera インターフェースを使って、regsvr32 なしで仮想カメラデバイスを作成できます。将来のブリッジプロセスではこの方式の採用を検討しています。

9. コード例

9.1 基本的な配信

#include "iron_vcam.hsp"

    screen 0, 640, 480
    vcam_create 640, 480, 30
    cam = stat

    repeat
        redraw 0
        color 0, 0, 64 : boxf
        color 255, 255, 255
        pos 10, 10 : mes "Live from IronHSP!"
        redraw 1
        vcam_send cam
        await 33
    loop

9.2 スクリーン領域の選択送信

#include "iron_vcam.hsp"

    ; 1920x1080 ウィンドウの中央 640x480 を送信
    screen 0, 1920, 1080
    vcam_create 640, 480, 30
    cam = stat

    repeat
        redraw 0
        ; ... 描画処理 ...
        redraw 1

        ; ウィンドウ中央部分のスクリーン座標を計算
        sx = ginfo_wx1 + (1920 - 640) / 2
        sy = ginfo_wy1 + (1080 - 480) / 2
        vcam_send_region cam, sx, sy, 640, 480

        await 33
    loop

9.3 hspcv4 との連携 (カメラ映像にエフェクト)

#include "iron_vcam.hsp"
#include "hspcv4.as"

    cam_w = 640 : cam_h = 480
    vcam_create cam_w, cam_h, 30
    vcam_handle = stat

    ; 物理カメラを開く
    cv4_video_open 0, "0"

    screen 0, cam_w, cam_h

    repeat
        ; カメラからフレーム取得
        cv4_video_read 0, 1

        ; エッジ検出エフェクト
        cv4cvt 2, 1, CV4_BGR2GRAY
        cv4canny 3, 2, 50, 150, 3

        ; HSP 画面に表示
        redraw 0
        cv4getimg 3, bmscr
        redraw 1

        ; 仮想カメラに送信
        vcam_send vcam_handle

        await 33
    loop

9.4 接続状態の監視

#include "iron_vcam.hsp"

    vcam_create 640, 480, 30
    cam = stat

    screen 0, 320, 100

    repeat
        redraw 0
        color 240, 240, 240 : boxf

        if vcam_is_connected(cam) == 1 {
            color 0, 128, 0
            pos 10, 10 : mes "状態: 配信中"
        } else {
            color 200, 0, 0
            pos 10, 10 : mes "状態: 待機中 (ブリッジ未接続)"
        }

        color 0, 0, 0
        pos 10, 40 : mes "ESC で終了"
        redraw 1

        ; 接続状態に関わらずフレームは送信し続ける
        vcam_send cam

        getkey k, 27
        if k : break
        await 100
    loop

    vcam_close cam
    end

10. トラブルシューティング

症状原因対処
vcam_create が 0 を返す hspvcam.dll が見つからない / パラメータが不正 DLL がランタイムフォルダにあるか確認。width/height/fps は正の整数を指定
フレームが送信されない ハンドルが無効 vcam_create の戻り値が 0 でないことを確認
vcam_is_connected が常に 0 ブリッジプロセスが起動していない ブリッジプロセスを起動するか、OBS Virtual Camera を使用
映像がティアリング (ちらつく) プロデューサとコンシューマの書き込み/読み出しが衝突 フレームレートを下げるか、ブリッジ側でダブルバッファリングを実装
映像が上下反転している ピクセルデータの走査方向の不一致 共有メモリのデータはトップダウン方式。ブリッジ側で変換が必要な場合あり
色がおかしい (赤と青が入れ替わる) BGRA と RGBA の混同 共有メモリのデータは BGRA 順序。RGB を期待するブリッジでは B/R の入れ替えが必要
メモリ使用量が大きい 高解像度の共有メモリ 1920x1080 BGRA = 約 8MB。不要になったら vcam_close で解放
パフォーマンスのヒント:
  • フレームレートは用途に合わせて設定 (配信なら 30fps、プレゼン用なら 15fps で十分)
  • 解像度は必要最小限に (640x480 で約 1.2MB/フレーム、1920x1080 で約 8MB/フレーム)
  • vcam_send はスクリーン DC からの BitBlt を伴うため、描画完了 (redraw 1) 後に呼び出すこと
